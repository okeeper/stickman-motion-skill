# Demo 验证记录

本记录对应仓库中三支 36 秒成片。验证环境为 Python 3.10、锁定的 Pillow / NumPy 依赖与本机 FFmpeg。它记录实际检查范围，不构成作品质量评分。

## 已检查的实际产物

三支 MP4 均经过 ffprobe 读帧统计，以及 FFmpeg 对全部视频、音频的完整解码。

| 成片 | 时长 / 帧数 | 画面 | 音轨 | 解码后峰值 |
|---|---|---|---|---|
| negative-ride | 36 秒 / 1080 帧 | 1280×720，30 fps，H.264 | 48 kHz 双声道 AAC | -14.39 dBFS |
| binary-search | 36 秒 / 1080 帧 | 1280×720，30 fps，H.264 | 48 kHz 双声道 AAC | -14.73 dBFS |
| complex-rotation | 36 秒 / 1080 帧 | 1280×720，30 fps，H.264 | 48 kHz 双声道 AAC | -14.04 dBFS |

详细机器结果见 [media-check.json](media-check.json)。音轨已检查长度、有限值、非静音与峰值，没有削波；这些检查不等于听感审查。

## 画面检查与本轮修正

检查了每支六个主要阶段的联系表，以及从编码后视频抽取的连续动作序列（3 fps）：

- 反向车 20.8–24.4 秒：主动反向后跳上车、触碰启动、乘车移动。
- 二分查找 28.2–32.4 秒：揭晓匹配值、开门、伸手取物和举起目标。
- 复数旋转 13.8–17.4 秒：抵达 -1、伸手取物和进入携带姿态。

本轮把二分查找改为隐藏的升序值，避免目标值和门索引直接相同；把取物统一为连续的手部路径；把承重脚从身体呼吸起伏中分离；复数携带姿态使用稳定的世界方向，避免角色转身造成道具跳位。

可复核的关键帧：[反向车](posters/negative-ride-contact-sheet.jpg)、[二分查找](posters/binary-search-contact-sheet.jpg)、[复数旋转](posters/complex-rotation-contact-sheet.jpg)。三支保留了完整目标与结果，公式位于动作空间之外；复平面中途只显示轨迹，到达后再展示对应等式。

## 自动行为检查

[测试代码](../tests/test_demos.py) 覆盖：

- 负数场景的速度符号、连续反号、行驶位移及停车边界。
- 二分查找全部 16 个可存在的目标：每次排除仍保留目标、区间缩小、至多五次查询；另检验缺失目标、无序和重复值的失败输入。
- 复数四次乘以 i 的结果、单位模长和屏幕中的逆时针方向。
- 三支共 3240 个时刻的角色头部画面边界，以及按钮接触窗口的实际腕部位置；接触误差小于 0.01 个逻辑像素。这是几何检查，不是轮廓遮挡证明。
- 同时刻重渲染像素一致、运动中的不同时刻画面确实变化、未知场景及非法 CLI 参数被拒绝。
- 合成音频可复现、长度正确、非静音、无无效数值、无削波。

## 尚未完成的检查

本轮使用关键帧、连续抽帧与自动解码；未完成全片正常速度的人工观片和听审，也未做观众静音理解度测试。简单骨架仍有姿态突然切换，固定镜头没有验证大尺度场景变化，低端手机上的阅读体验尚未测试。

二分样片只演示目标存在、值唯一的有序数组；不存在目标、重复值等分支不在故事范围。角色运动是动画编排，不代表完整物理仿真。后续改进应记录具体时间戳及观众反馈，再更新 skill 的制作规则。
