# 剧本工作台：从主题快速写到可制作场景

用于调用本 skill 写新故事、改无聊的脚本或准备分镜。方法依据见 [因果剧本](cinematic-storytelling.md)，原片依据见 [情节拆解](../docs/reference-story-analysis.md)。这是 agent 的创作工作法，不是可以自动评价好看程度或一键渲片的程序。

## 接到任务时

先从上下文取主题、受众、片长、调性、交付范围和用户已有选择。缺失但可合理决定的内容直接假设并简短说明；只询问真正会改变方向的信息，已有授权内继续工作。

- **只要故事创意**：交付走向不同的方案及推荐理由，重点说明现象、变化和结尾，不先堆公式或镜头。
- **要完整脚本**：自主选定可成立的方向，交付下述因果摘要、关键事件、回收和制作分镜。
- **反馈“太无聊、太蠢、像上课”**：先定位现稿的具体薄弱事件，再改发展方式。不要只换标题、拉长观察、加摔倒或提高动作密度。
- **要视频**：在同一任务中把剧本发展、规则核对、关键段试做和制作连续完成；不把此文解释成需要用户逐步批准的流程。

## 开发用的简短底稿

先写自然语言，足以让不了解知识点的人读懂因果：

```text
主题 / 想让观众感受到的性质：
最初可见的异常现象：
角色此刻想靠近、确认、避开或保住什么：
观众最初的问题和可见线索：
关键操作，以及它带来的新处境：
原先办法为什么需要改变：
同一对象或规则在后段的新作用：
关键选择凭什么成立，付出什么：
结尾如何回答最初问题，留下什么变化：
```

这些问题没有答案时，先改故事，不用演员站着读公式填补。无需每个故事都有误判、对手、牺牲或身份反转。

## 从知识性质找戏剧变化

需要快速构思时，从真正成立的性质出发找行动后果，不先把主题套进门锁或运输车。以下是方向提示，不是现成剧情或新增世界定律。

| 知识性质 | 可以产生的故事变化 | 需要保留的边界 |
|---|---|---|
| 二分查找逐次排除不可能区间 | 信息变清楚的同时，路线、暴露范围或可选位置发生改变 | 有序前提成立；查询结果不能凭空改变原数组 |
| 指数/递归让局部操作反复作用 | 起初可控的复制、任务或反馈累积成必须重新处理的规模 | 明确基数、递归规则和停止条件；不等于现实能量凭空增加 |
| 对称、逆运算与表示变换 | 同一对象换个方向、视角或表示，原先的阻碍成为可用关系 | 明确哪个量不变、哪个量改变，以及逆操作的条件 |
| 守恒与约束 | 不能同时保住两项好处，角色必须分配、交换或放弃 | 画面中资源、质量或能量有来去，不用神奇补给解围 |
| 导数与局部变化 | 眼前的趋势支持一个判断，范围扩大后需要重新检查 | 局部结论不自动推及全局；模型与测量分开 |
| 概率与重复试验 | 一次结果不说明全部，角色改变收集证据或承担风险的办法 | 不把好运、短样本或一次成功写成一般证明 |

把性质写成可见的动词与反馈：比较、排除、累积、反转、分配、逼近、抵消。然后追问这项反馈会让人物失去或获得哪一种选择。数学若只是给按钮贴一个名称，继续改故事。

## 关键事件表

先覆盖真正改变走向的事件，再补必要的动作连接；不要求每一抬手都填全表。

| 字段 | 写到可以拍摄的程度 |
|---|---|
| 之前 | 角色知道什么，身体/资源/关系处在什么状态 |
| 观众期待 | 观众现在等哪个结果，有哪些预测依据 |
| 选择与动作 | 为什么采用这个办法；身体接触什么、从哪里到哪里 |
| 世界回应 | 哪项规则或对方行动给出反馈；输入、触发和结果可见 |
| 之后 | 改变了哪项信息、办法、位置、权限、资源或关系 |
| 接向后文 | 哪个未解决的问题或新机会，使下一段有理由发生 |

写完用“因为上一段的具体结果，所以这段才发生”连成一段故事。无法连接的事件可能需要删去、重排或建立来源；不用“然后又来了一个机关”替代因果。

## 两张短表支撑兑现

**对象与规则的来路**：只列重要对象。

| 对象 / 规则 | 第一次怎样出现和被读懂 | 此时作用 | 后来怎样换用途或改变关系 |
|---|---|---|---|
| 稳定 ID | 角色看到/听到/接触的证据 | 疑问、资源、工具、阻碍等 | 不只是再出现，而是影响选择或结果 |

**铺垫与回收**：只列故事实际用到的承诺。

| 前面的细节 | 观众当时如何理解 | 后来兑现在哪项行动或认识 | 移去细节后会怎样 |
|---|---|---|---|
| 可见动作、反馈、声音或限制 | 不必立即解释全部用途 | 使结尾可回想、可理解 | 检查它是否真的必要 |

数学假设、对象身份与四类语义操作继续使用 [规则规格](concept-scene-spec.md)。隐喻的传送、发光和主动行为单独列为故事约定。严谨证明任务另外交付假设与推导，不把实验或公式生成的动画写成证明自然规律。

## 转为制作分镜

用实际事件估时，给出可调整的时间预算。默认每段包括：

> 时间预算；画面与角色注意；行动、支点和接触；对象/规则的具体反馈；角色和观众此刻知道什么；关键声画重音；连接下一段的结果。

重要表演写可执行动词：探身后收手、重心留在退路、手先摸稳再交重量、挡开后转向空隙、想追却刹住、释放控制后等待对方回应。少用“疑惑、帅气、震撼”代替动作。

快动作按正常速度设计。慢的是新关系的阅读、判断和恢复所需时间；一段停顿要标出期间新增的线索或选择。删去没有事件变化的留白，再判断片长，而不是为了够 90 秒延长等待。

新动作不必迁就现有演示的走跑跳范围。保留剧情所需动作，同时标出新的抓握、交接、碰撞或群体行为需要试做；把创作假设和已实现能力分清。

## 自审后再交付

对最弱段落使用 [反事实审稿](cinematic-storytelling.md#写完后做因果审稿)。优先修正能影响整条故事的缺陷，不用加形容词掩盖。

默认完整脚本包含：

1. **一句话故事与核心看点**：说人物遭遇和变化，知识点不替代剧情。
2. **因果梗概**：能读成一个故事；关键选择有来由，结尾有前文依据。
3. **关键事件和回收**：可与分镜合并，避免重复填写大表。
4. **制作分镜**：动作、知识反馈、镜头动机、声音与时间预算。
5. **规则边界和待试做项**：分别标记数学事实、世界约定、文本自审与未完成的动画验证。

用户只要初稿或短故事时，按需压缩这些项。不要把没有观众反馈的自审称为叙事效果已验证。

## 可直接使用的任务

**从主题写脚本**：

```text
使用 $stickman-motion-skill，围绕【主题】写一支【大致片长】的无台词故事。
先找到值得接近或回避的异常现象，再让角色的选择不断改变处境。
让核心概念决定一次重要转折；同一对象或规则在后段获得新的作用。
按剧本工作台交付因果梗概、制作分镜、铺垫回收与数学/故事边界。
先找出并修正最弱的重复或无来源转折。这次只交付脚本。
```

**修改已有脚本**：

```text
使用 $stickman-motion-skill 修改下面的剧本。先指出最具体的三处无聊、
不合理或可提前解决的事件，再重写因果，不靠加机关、加摔倒或延长停顿。
保留有效设定和用户已确定的选择；说明哪些反馈改变了人物办法和观众期待。
[粘贴当前脚本]
```

**把成熟脚本制作成视频**：

```text
使用 $stickman-motion-skill 制作这份脚本。沿用已确定的故事和规则，
先试做最不确定的关键交互，按实际结果修正衔接后完成全片。
交付有声 MP4、可编辑 TS 工程、剧本及实际验证记录。
[附脚本路径]
```
