# 重量、蓄力与弹性

用于需要承重、跳跃或着地冲击的动作。先读 [原片观察与设计依据](../docs/weight-motion-study.md)，运行入口见 [Web 工程说明](../web/README.md)。曲线关节只负责轮廓；身体运动、接触约束和关节表演分别处理。

## 当前模型与单位

世界坐标以米、秒、千克为约定，`y` 向上；画面比例由相机统一转换。`physics.ts` 的髋部代理点承载有效质量，`rig.ts` 生成骨架，`render.ts` 负责视觉表达。这里的髋部不是逐肢体质量加权的真实全身质心。

- **预备**：有界的最小跃度曲线控制下蹲，保证竖直地面反力非负。极端低重力参数下，模型会延长实际下蹲时间以保持接触。
- **做功**：演示模型设 `W = 1400 × charge × effort` 焦耳。这是可调的艺术设定，不是人体生理公式。它决定蹬伸后的水平、竖直动能与上升势能：`W = m g Δh + ½m(vx² + vy²)`。质量增加但做功不变，起跳速度降低。做功不足则报错，不能让身体凭空离地。
- **腾空**：`x = x0 + vx t`，`y = y0 + vy t − ½gt²`。重力在一次动作内恒定；没有支持力，也不对飞行时间再套缓动。允许超常发力，但要保留前面的准备与后面的冲击。
- **落地**：延续碰撞前速度。腿部等效弹簧基准 `k = 10000 N/m`；较重或较高重力时提高刚度，使静态压缩不超过 `0.08 m`，留在脚跟转动与骨长可达范围内。阻尼比随弹性参数改变。`N = max(0, k(rest − y) − c vy)`，不会向下拉地面；达到伸展边界后可再次离地。水平弹簧阻尼吸收向前动量，这是简化支撑模型，尚未约束完整摩擦条件。
- **跟随**：上身使用受驱动的角弹簧；头部、摆臂和收腿形成视觉滞后。不能声称所有关节都由物理求解。

落地与上身按固定 `1/480 s` 步长预计算，再按绝对时间采样。浏览器丢帧或切换视频帧率不能改变动作结果；飞行段使用解析解保持重力轨迹。不要把渲染帧间隔当成物理步长。

二次弹起时脚随身体水平移动，下次触地才冻结新的支撑位置。高弹性动作会自动延长尾段，直到位置和速度连续一段时间满足稳定条件，避免循环播放在回弹半途截断。

## 复用接口

```ts
import {createMotion, PRESETS} from './physics';
import {skeleton} from './rig';
import {draw} from './render';

const motion = createMotion({...PRESETS.heroic, mass: 80});
const t = frame / fps;
const state = motion.at(t);
const pose = skeleton(motion, state);
draw(context, motion, t, {debug: false, preset: 'heroic'});
```

`createMotion()` 输入完整的五个参数：质量、重力、蓄力时长、发力强度、落地弹性；超出支持范围或不可完成的发力会抛错。它输出运动时刻、位移、速度、地面反力和起跳/碰撞/回弹事件。音效从这些事件生成，不再凭固定秒数对齐。

场景代码决定角色想做什么，动力学决定身体怎样移动，骨架决定四肢怎样配合。把新动作接入概念故事时，保留对象交互、规则卡和镜头逻辑；本模块只覆盖单次跳跃研究，不能直接替代攀爬、翻滚、抓物或任意障碍接触。

## 接触和轮廓

- 双腿各两段 `0.45 m`，双臂两段分别为 `0.285 m`、`0.275 m`。IK 必须报告不可达距离，不能悄悄伸长骨头。
- 支撑阶段固定脚尖，脚跟绕脚尖转动；飞行阶段根据髋部位置收腿，着地前展开到相对身体的落地姿势。不要提前把空中脚锁到地面，造成断腿或悬停。
- 本示例为近侧面的角色，两个膝盖朝运动方向弯曲；远侧肢体降低明度。不是全朝向通用人体绑定。
- 曲线路径只柔化关节附近的轮廓，关节连接与末端接触仍以骨架数据为准。

## 验证动作是否成立

自动检查涵盖能量预算、腾空加速度、离地与着地速度连续、落地耗散、骨长、脚底不穿地、支撑点稳定、任意拖帧确定性、实际浏览器输入与成片帧数。

还要查看蓄力最深、离地前后、最高点、触地前后、最大压缩及回弹等连续帧，并以正常速度判断重轻、节奏和表演。慢放是定位工具，不是最终观感。GIF 会降低帧率，判断流畅度优先看 60 fps MP4。未做真人观片、听审或观众测试时须明确记录，不能以数值检查冒充艺术质量结论。
