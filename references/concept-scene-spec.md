# 概念与场景规格

## 规则卡

| 字段 | 需要回答的问题 |
|---|---|
| concept_id | 这条机制的稳定标识是什么？ |
| dramatic_need | 角色要解决什么处境问题，为什么有理由操作这条机制？ |
| proposition | 真正要表达的命题是什么？ |
| assumptions | 适用于哪些数、单位、坐标约定、边界情况？ |
| embodiment | 哪个可见对象承载它？ |
| affordance | 角色可以推、拉、旋转、连接、拆分还是触发什么？ |
| state_before / state_after | 动作具体改变哪个状态？ |
| visible_feedback | 观众如何看到变化与结果？ |
| decision_basis | 角色当时已知什么、为什么选这个办法；哪些信息只有观众知道？ |
| misconception | 若剧情确有误判，其合理依据是什么？可以不设置，不强制角色先犯错 |
| payoff | 已建立的机制、物件或能力，后面如何换用途、组合或有意识地再使用？ |
| cost_and_continuity | 行动消耗了什么、改变了什么；下一场必须保留哪些伤情和资源状态？ |
| fiction_boundary | 哪些只是故事中的物理化约定？ |
| verification | 如何核对事实，哪些还未验证？ |

不要把“旋转一个符号”自动当作“旋转其代表的数学对象”。两者可在故事中相关，但必须设计清楚触发关系。

## 四类语义操作

1. **expression_edit**：改变表达式，例如把加号换成乘号。新表达式重新求值，允许经过明确的编辑中间态。
2. **evaluate**：依据给定输入得到结果，例如 3×(-1)=-3。
3. **equivalent_rewrite**：保持指定条件下的数学含义，例如 x+x=2x。符号系统核验时保留假设。
4. **spatial_metaphor**：把概念映射成可操作场景，例如有向位移控制运动方向。明确映射，勿宣称故事装置是现实物理定律。

同一动作可以组合多个操作，但要记录各自发生的时间和对象。输入还在编辑时，不要显示一个看似已成立的错误等式。

## 分镜的最少字段

时间范围；角色目标与已知信息；关键选择的理由；当前身体/资源状态；动作与接触点；涉及知识时的语义操作；结果与持续后果；画面布局与注意点；镜头动机；音效事件；阅读/反应停顿。普通观察、准备、反应和人物关系动作无需硬贴一种数学操作标签。

关键接触还应记录抓取、释放和碰撞时刻。重复出现的相同字形使用不同对象 ID，防止公式变形时错误配对。视觉上的字形身份与数学表达式身份分别管理。

## 校验尺度

- 有限数值计算：精确计算或适当精度，并检查显示舍入。
- 一般恒等变形：保留定义域和假设，使用符号化简/推导；不确定时不要宣布验证成功。
- 根式、复数、对数和极限：处理主值、分支及收敛条件。
- 物理：检查单位、守恒关系与模型假设。
- 算法：检查前置条件、边界输入及关键不变量；用对应示例复现。
- 视觉隐喻：检查它是否使观众推断出额外的错误命题。
