# 《Animation vs. Math》仿写提示词

历史配置：这是针对《Animation vs. Math》的专用提示词，保留供用户明确选择该写法时参考。当前默认入口为 [导演与剧本](concept-story-directing.md) 和 [分镜与提示词](director-workflow.md)，按题材选择结构；用户的明确要求优先。

采用这一历史配置时，可按需要研究下列具体场面，结合新题材重新设计；无需将全部场面强制套入每一支新片。

## 原片中要在新稿里看得见的东西

| 对照点 | 新稿必须写出的可见事件 | 依据 |
|---|---|---|
| 身体先于知识介绍 | 先给角色一个具体身体状态和即时反应，再让他注意到手边的小对象 | 开场恢复、摸头、站起与接近符号 |
| 用手试出世界规则 | 操作符号本体：掰、拖、拼、转、拿走或插入一笔；清楚显示输入变化、结果生成与身体反馈 | 开场线条编辑与算术操作 |
| 玩耍长出复杂性 | 角色因反馈有趣主动换组合；重复、分组、数量或表示发生变化，结果里留有下一步可操作的部分 | 前段算术、阵列、幂与根式的连续探索 |
| 异物留下再回来 | 新结果中出现一次不能完全解释的主动行为；后面通过相同轮廓、动作或声音身份认出它 | 早先表达式与后续相遇的联系 |
| 符号能反过来行动 | 熟悉物件或系统开始主动追、抢、躲、阻挡、变形或坚持某件事；它的回应来自自身规则 | 中段表达式的独立行为与交手 |
| 攻防相接 | 角色出手，对方回应，空间/控制发生改变，迫使下一招；画清接触、支点与受力 | 快动作中的格挡、躲避、反击与失衡 |
| 安静段产生新办法 | 人物亲手重排、测看或展开刚才留下的对象，把它变成另一种可操作表示 | 点、轴、圆与波形的建立过程 |
| 认识推动场面升级 | 先前的小操作在更大结构或组合中再次生效，直接改变行动范围、控制权或通路 | 图形和表达式参与后段大范围行动 |
| 冲突后重新面对同一对象 | 回到近距离，用一个具体动作改变双方的互动方式，再留下仍在运行的世界 | 尾段小尺度互动与对象继续活动 |

这份表描述一段完整遭遇的默认展开。短片压缩为“触觉发现—规则反过来影响人物—换用途解决—回到同一对象”，保留具体事件和变化。不要把多个相同按钮操作当作压缩版。

## 提示词 A：构思一个贴近原片的故事

可直接作为 agent 的编剧任务；方括号由用户信息或合理假设补齐。

```text
你正在为 stickman-motion-skill 构思一部无台词火柴人动画。
主题：[知识主题]。大致时长：[时长]。受众：[受众]。
按《Animation vs. Math》的具体事件组织方式写，画面默认黑场、白色知识对象、
橙色空心头主角。让读者读完就能想象人物在其中动手、玩耍、交手和发现。

从一个有身体状态、会正常反应的人开始。他没有拿着任务清单入场。
第一件值得接近的东西要很小、可触碰；先用一次明确的手部操作给出反馈。
操作直接改变知识对象本体，不能只按一个写有公式的按钮。

接着让他因为好奇和玩心，把刚试出的操作用得更大胆。
每项新结构都从上一项操作的结果里产生，保留身份、位置或可辨认的部件。
其中有一个结果第一次出现时表现出自己的行为，留下一个具体而未解释的疑问。
后面让观众认出它，它对主角的行为作出有规则的回应。

把主角与这个对象/系统的关系写出变化：最初试它，随后被它影响，
再设法应对和理解它。对手可以是知识对象自身的坚持或反馈，别另外空降怪物。
写一段正常速度的连续交手：主角动作→对象回应→落点或控制变化→下一动作。
动作要使用已认识的符号、线条、结果或几何关系；不靠普通武器替代知识作用。

冲突后留一段能读懂的新探索：他亲手把现有对象重新组合、拆开或换一种表示，
看见刚才没看见的关系。随后用这项具体发现处理前面那个对象，
让场面、空间或双方控制关系明显改变。新增知识需要在使用前有一次清楚反馈。

结尾再次面对同一个对象，写一个可见的停手、归还、让位、接受或共同操作，
显示互动方式已经改变；世界在人物的这次经历之后仍继续运行。

先自主选定一个最适合该主题的遭遇，再交付：
1. 一句话故事，以及该知识性质为什么不可替换。
2. 一段可以连续读完的故事，写发生的事，不写创作原则。
3. 关键场面：首次手部操作、异物第一次主动回应、连续攻防、
   重新探索获得办法、先前发现的后段使用、结尾再次相遇。
4. 一张对应表：上述场面如何具体体现参考片的处理方式。
5. 数学事实与故事约定；对最可能显得重复、装傻或凭空解围的一处先修改。

人物有正常判断，也有玩心、自信、惊讶和受挫；不能为了剧情忘记刚看见的规则。
不要把故事写成“找到钥匙—过三关—到出口”，不要让他长时间站在公式旁。
不要重演原片的具体符号组合、对手与整套遭遇；要重新设计本主题的可操作事件。
只写到本次要求的交付范围，不生成视频或安装依赖。
```

## 提示词 B：把选定故事写成制作脚本

```text
沿用下面已选定的故事，写成可供 TypeScript 动画制作的无台词分镜脚本。
保留其《Animation vs. Math》式的触觉操作、对象主动回应、知识空间展开，
以及小尺度探索与快速行动交替的观感。不要重新改成关卡任务。
[故事]

先把整段读成真实发生的遭遇，再根据事件估时。
每个场面写清以下六项，可用表格或连续场景稿：

时间预算 / 背景与对象现状：什么已经在场，什么刚由哪项结果生成。
画面动作：先看向哪里，哪只手碰到哪个部位；脚踩什么，重心和目标各到哪里。
知识变化：改的是字形、输入、求值、等价表示还是空间隐喻；结果怎样进入画面。
对象回应与人物反应：对方做什么；角色怎样护身、换握、刹住、绕开或再出手。
声音设计：实际接触声、知识反馈声、环境声分开；写触发点、强弱和尾音。
音乐设计：探索、紧张、发现、余波之间何时进入、密集、留空、回落；
           这是新片的原创配乐指令，不冒充原片已经听辨的乐器或音乐段落。

首次编辑要让观众看见手的操作、输入和结果；操作熟悉后加快复用。
连续行动写出具体的“做什么—被怎样应对—借什么接下一招”，
不能用“大战一番”“帅气闪避”“震撼爆发”概括。
人物会走、跑、跳、扑、挡、摔、滚、起身和冲刺，但动作由当前物件和局势决定。
执行段按正常速度，停顿必须让观众读到新的判断、线索或关系。

每次扩大画面规模，保留一个熟悉对象作参照；新结构沿已有点、线、轨迹展开。
同一对象再次出现，保留轮廓或动作身份；已经发生的疲劳、损失和位置不能重置。
高潮列出它用了哪项前段发现，以及如果没有这项发现该动作为什么做不到。
结尾给出与首次接触可比较的行为，再收束声音。

附最少的对象身份、规则假设、关键声画事件和需要试做的新动作。
本次交付脚本；时间是预算，不能写成已经渲染或观片通过的实测结果。
```

## 提示词 C：审掉“看着像，事件却不像”的稿子

```text
按《Animation vs. Math》仿写配置审改以下脚本。
[脚本]

先逐项定位具体场面：
- 第一项知识是否真由手和身体试出来，还是开场已经知道全部规则？
- 下一结构是否来自上一操作，还是一块新面板突然出现？
- 角色是否真的在玩、应对和重新发现，还是依次演示知识清单？
- 先前异物回来后是否仍有主动回应，还是等着主角操作的工具？
- 连续动作是否由对方回应迫使改变，是否借用了知识对象的形态和性质？
- 安静段有没有产生后面能用的新表示，高潮是否真使用了它？
- 结尾再次面对同一对象时，是否有可以看出来的互动变化？

对缺项直接重写相关事件，不用补一句“他意识到……”或一个情绪标签交差。
删除只重复确认同一规则的尝试；缺少新办法时重做探索，不追加奖励或救援物。
保留数学前提、正常判断、对象身份和身体连续性。
交付修订脚本，并简短列出“原事件→改后事件→更接近参考片的具体之处”。
这是创作自审；不能据此宣布观众一定觉得精彩。
```

## 使用时的顺序

构思任务用 A；选定故事的完整脚本用 B；已有弱稿用 C。用户要求从主题直接获得完整脚本时，连续完成 A 的故事开发与 B 的分镜，不停在方案确认。原片对照和事件成立情况随稿简短列出；通用分镜字段见 [工作台](story-workbench.md)，数学边界见 [规则规格](concept-scene-spec.md)。

细读原片时区分画面事实和解读。新片的音效与音乐可以完整设计；尚未听辨的原声，不填写成参考片事实。当前文本试写记录见 [投影题材试写](../examples/reference-prompt-trial.md)。
