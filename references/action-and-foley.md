# 正常速度的动作与拟音

用于有走、跑、跳、失衡、跌倒、翻滚、冲刺和恢复的火柴人动作戏。人物是生活在数字空间里有判断力和身体边界的人：会察觉危险、选择落点、保护头部、喘气、失去平衡并改变计划。动作由处境引起，声音由身体与世界的接触引起。

实际起点：[《断点》11 秒有声试片](../demos/action/README.md)、[场景代码](../web/src/action/model.ts)。它验证一条侧面撤离路线，新增故事仍需编排；不是任意地形、任意打斗的完整人体求解器。

## 先辨认参考片怎样处理动作

参考 [Animation vs. Math](https://www.youtube.com/watch?v=B1J6Ou4q8vE)，以下基于原片连续帧观察；原片截图与下载文件仅在本地研究目录，未发布到仓库。

- **04:09.38–04:10.88**：身体很快改变方向并交替收放四肢，空中姿势不对称，髋部移动时并未等每条手臂“动画播放完”。动作通过几个清楚轮廓和紧凑过渡完成。
- **04:11.00–04:11.88**：伸展、挥动与收拢有明显速度和幅度差别，身体会顺势前倾；不是只旋转一条胳膊，其他部位保持站姿。
- **04:18.90–04:20.57**：翻转后由身体近地到手臂支撑、上身恢复。受到较重冲击后的恢复比先前的快动作更慢，后果延续到下一姿态。

这说明“利索”不是全片等倍加速，也不是所有关节都始终柔缓。执行要快且轮廓明确，动作前后的观察、卸力和判断按处境留时间。原片的帧率和夸张不能用来反推真实体重或重力参数。现有研究没有完成原片逐项音色听辨，不能把素材选型称为原片音效复刻。

## 步态和速度各有用途

先决定人物要到哪里、何时需要加速或躲避，再选择步态。默认正常速度播放；慢放用于检查。不能把同一个走路循环加速后同时称作跑、冲刺和撤退，也不能让每次小跳都先蹲一秒。

| 动作 | 身体与支撑 | 本试片的节奏示例 |
|---|---|---|
| 走 | 交替承重，存在双脚支撑，摆臂较小，头先注意目标 | 约 0.44 秒一步，巡行约 1.35 m/s |
| 跑 | 支撑变短，两次支撑之间有短腾空，膝与肘主动弯曲 | 约 0.29 秒一步，约 3.3 m/s |
| 冲刺 | 更短支撑与更大步幅，躯干前倾，摆臂配合蹬地 | 约 0.22 秒一步，约 5.6–5.7 m/s |
| 助跑跳 | 最后一步压低再蹬伸，继承已有水平速度，空中收放腿 | 最后准备约 0.18 秒，腾空约 0.685 秒 |
| 跌倒接滚翻 | 趾部受阻，身体继续前进，手先保护，再收身转移支撑 | 跌倒约 0.37 秒，滚翻约 0.60 秒 |
| 起身、刹停 | 脚接回重量，起身接跑；制动时身体平衡后移 | 起身接跑约 0.36 秒，刹停约 0.75 秒 |

以上是本路线的参数，不是所有人物的固定标准。质量、能力、路面、受伤、惊吓和目标都会改变动作。大跳可以更夸张，但发力和着地代价仍可见；助跑本身已经积累水平动能，无需再次从静止起步。

## 支撑与片段交接

[stunt.ts](../web/src/stunt.ts) 提供速度积分、交替步态、固定骨长、蜷身姿态和地面支撑修正。[model.ts](../web/src/action/model.ts) 编排本路线的助跑起跳、跌倒与恢复。

- `speedTrack(keys,start)` 对速度解析积分，转换动作时保留位置与水平动量。
- `locomotion(track,from,to,cadence)` 输出 Rig 和实际落脚事件；承重阶段足部使用世界坐标锚点，跑步的自由脚采用收腿与前送轨迹。
- `tuckedPose` 先收身再转动，`floorSupport` 处理本侧视场景的身体近地约束。手掌撑地用实际腕部目标，滚翻体音根据实际支撑部位变化生成。
- 助跑跳用最后一步的压缩与蹬伸、解析重力、非对称收腿和落地阻尼。落地速度进入压缩，不立即归零。
- 起身继承蜷身末姿并接入下一步，不插入中立站姿。交接检查包含手、脚尖、头和躯干，不能只看髋部曲线。

《断点》的跌滚属于编排表演结合几何约束，未实现完整关节碰撞、肌肉、全身质量分布、任意墙面或双人对抗。`transfer` 仍只覆盖原来的同高移动支撑；不要把一条试片泛化成全部人体行为。需要格挡、攀爬、踢打或被击飞时，按受力与接触设计新增动作，并先做短试片。

## 动作不是配一个提示音

接触、布料、气流、呼吸与环境各自承担职责。每次有听觉意义的落脚、碰撞、抓取、刹擦和机械变化都应有相应事件；轻微转头不必硬加一声“嗖”。不能用密集音效掩盖不清楚的动作。

| 事件 | 声音处理 |
|---|---|
| 走、跑、冲刺落脚 | 同材质的多份脚步素材，按步态改变力度、短促感与轻微音高差；声音时间直接来自落脚 |
| 起跳与落地 | 鞋底蹬擦与短气流；落地组合鞋底接触和承重低频，腾空没有脚步声 |
| 扶地、肩背或身体触地 | 分开时间与力度；体音跟实际支撑转移，手掌不播放重型闸门声 |
| 滚翻、快速摆动 | 布料摩擦与适量空气声，允许声音尾部跨过下一个动作 |
| 刹停、恢复 | 短刹擦、较弱的收步和呼气，不把每次接触都做成爆炸 |
| 数字空间 | 重置报警、地面弹起和闸门独立配声；位置、距离与遮挡按实际场景处理 |

本工程使用 [Kenney Impact Sounds](https://kenney.nl/assets/impact-sounds) 与 [RPG Audio](https://kenney.nl/assets/rpg-audio) 的 CC0 脚步、碰撞及布料素材；气流、呼吸与报警纹理由程序合成。素材来源、处理方式、原始与派生指纹在 [bank.json](../motion/public/audio/bank.json)，原始许可随样本保留。合成呼吸层不能宣称是录制人声。

[foley.mjs](../web/src/foley.mjs) 是浏览器与导出的共同 PCM 混音器。网页默认 1×，点击播放后启用声音，以音频时钟驱动画面；拖帧会暂停声音。导出在 48 kHz 采样上定位事件，局部导出保留入点之前的尾音。素材与细小变化按事件 ID 固定，不因反复拖帧改变。

## 试做与验收

```sh
python scripts/init_web.py output/my-action --scene action
npm --prefix output/my-action/motion ci
npm --prefix output/my-action/motion run prepare:audio
# 以下在新工程 motion/ 中运行
npm run dev
npm run test:action
npm run render -- --scene action --fps 30 --from 5.3 --to 6.8 --out ../renders/fall-roll.mp4
npm run render -- --scene action --fps 60 --out ../renders/final.mp4
```

打开 `/action.html`。先按正常速度看人物目的、重心、脚步密度、接触与衔接，再慢放定位具体问题。实际 MP4 中检查落脚是否同步、材质是否可辨、声音是否重复疲劳或盖过关键事件。数值检查应覆盖骨长、地面、支撑锚点、解析腾空、完整姿态边界和任意拖帧；音频另检查削波、前后裁切、素材缺失和失败输出保护。

正常速度观片、完整听审与观众理解检查分别记录。使用素材库、通过约束或提高帧率，都不能直接等同于“已经像真人动作片”。

素材首次通过 `scripts/prepare_audio.py` 准备，之后复用本地校验缓存；原始音效不随 Git 发布。混入成片的声音可直接播放。
