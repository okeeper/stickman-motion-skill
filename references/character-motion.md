# 柔和关节与连续表演

本文描述 0.2.1 的 Python 概念片引擎。它处理轮廓、姿态过渡和接触，但没有建立完整的跳跃动力学。需要真实重量、蓄力和着地冲击时使用新增的 [重量与弹性模型](weighted-motion.md)，不要把“曲线更柔和”等同于“动作更真实”。

当前骨架的实现入口是 [drawing.py](../scripts/demo_engine/drawing.py)，动作编排在 [performance.py](../scripts/demo_engine/performance.py)。`motion.py init` 会把这两个模块连同其余引擎复制到独立工程。三支样片共享这套实现；不需要按题材重写人物。

## 轮廓与骨架

肘、膝是控制点，最终笔画在关节两侧截取一段，用二次曲线相接，保留手腕和脚底端点。躯干有轻微曲率，肩部和头部通过颈线连接。单纯把折线端点画圆，仍会留下机械折角。

双腿在站姿下向各自外侧弯曲，走路时逐步朝行进方向弯曲。不要把角色朝向直接乘到左右膝盖的二值方向上；这会在转身时翻转膝盖，也会让站立双腿交叉成 X。

两骨段求解限制最远和最近可达距离。手臂使用连续的弯曲方向，并在手靠近肩部时允许透视缩短，避免二值肘朝向突然翻面。这是卡通曲线骨架，不是严格保持每一根骨段长度的解剖模型。接触是否可达，以返回的实际腕部坐标为准。

## 动作叠加

`actor(..., pose={"think": 0.4, "recoil": 0.2})` 接受姿态权重。`window(t, start, end, attack, release)` 给片段配置进入和退出；`progress` 使用五次曲线，端点速度和加速度为零。不要在某一帧直接把字符串从 idle 换成 celebrate，再指望提高帧率解决跳变。

手臂抬起时加入外侧弧线，避免手腕沿直线穿过肩部。呼吸、头部、躯干、摆臂使用不同幅度和相位；这些小幅运动叠加在有意图的姿态上。庆祝时脚保持承重，通过上身侧摆、膝部压缩和双手错峰形成变化。

跳跃把预备压缩、空中姿态和落地缓冲分开编排。不要把下蹲数值在落地帧从 0 瞬间改成 1。平滑曲线也不是所有运动的唯一答案：负数小车按照规则瞬间改变运行速度，人物需要表现承受这次变化。

## 脚与手的约束

`walk_track(t, start, end, x0, x1, floor_y)` 返回身体位置、脚的世界坐标、步态相位和承重状态。每只脚在支撑阶段固定在上次落点；摆动阶段沿平滑抬脚轨迹进入下次落点。左右方向、短步和停止都用同一套逻辑。结束移动后再恢复站姿，不能直接重置脚的位置。

```python
from demo_engine.drawing import actor, press_target
from demo_engine.performance import walk_track

track = walk_track(t, 1.0, 3.5, 200, 400, 620)
planted = track.pop("planted")
rig = actor(canvas, t=t, **track,
            right=press_target(t, 4.2, None, (455, 535)))
```

`Reach(target, weight, arc)` 从当时的真实手部姿态进入目标，而不是从另一个手写的“休息位置”开始；`weight=1` 时精确接触，结束后回到当前姿态。`press_target` 保留旧的 rest 参数以兼容调用，但不再使用冻结的 rest 坐标。

`pickup` 在抓取时刻让手和物体重合；携带姿态的切换藏在这个约束下。释放后让手逐渐收回，物体留在放置位置。测试必须检查交接前、当时、交接后，而不只检查某一个正确的静帧。

## 怎样验收

先看放大后的连续帧和正常速度视频，再回到全景检查叙事。特别检查站姿剪刀腿、肘部翻面、支撑脚滑动、手穿肩、姿态开始/结束跳变和取物断开。

`python -m unittest discover -s tests -p test_motion.py -v` 检查三条时间线的关节连续性、站姿、承重、实际接触、极近/极远目标、跳帧预览一致性及失败输入。数值连续不等于表演自然；在记录里分别写实际完成的自动检查、连续帧检查和人工观片，不以测试通过代替观感判断。

本次修改的实际视频对比见 [动作修正](../demos/motion/README.md)。
