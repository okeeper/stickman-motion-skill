# 从柔和关节到有重量的动作

这次解决的是 0.2.1 的不足：圆滑的肘膝和连续姿态改善了轮廓，但把跳跃整体套入平滑升降曲线，会使离地、下落与着地都像在缓动。关节不生硬，不等于身体有重量。

## 原片的实际观察

研究对象是 Alan Becker 的 [Animation vs. Math](https://www.youtube.com/watch?v=B1J6Ou4q8vE)。下面是对指定连续帧的观察，不是对原作者制作软件或物理参数的推断。原片帧图只保留在本地研究目录，不随本项目分发。

| 原片时段 | 连续帧中可见的动作 | 对本项目的启发 |
|---|---|---|
| [04:09.20–04:09.87](https://www.youtube.com/watch?v=B1J6Ou4q8vE&t=249) | 躯干方向发生变化，空中的两条腿收拢程度不同；头、躯干、四肢没有同时保持一个刚性姿势 | 用身体的移动组织全身，空中姿态保留不对称；此段不能当作标准原地跳的运动测量 |
| [04:11.20–04:11.83](https://www.youtube.com/watch?v=B1J6Ou4q8vE&t=251) | 伸展动作伴随显著的躯干前倾；后续收拢与展开形成清楚的强弱变化 | 发力需要改变整个身体的姿态，单独匀速旋转手臂不足以表达用力 |
| [04:13–04:20.5](https://www.youtube.com/watch?v=B1J6Ou4q8vE&t=253) | 冲撞之后出现翻滚、落下和恢复，而不是立即切回站姿 | 冲击后的恢复也是动作的一部分，必须给惯性和失衡留下时间 |
| [04:18.90–04:20.57](https://www.youtube.com/watch?v=B1J6Ou4q8vE&t=258) | 从蜷曲、翻转到背部近地，再由手臂支撑上身、慢慢坐起；不同身体部位依次接近支撑面 | 接触点会转移；恢复速度与碰撞速度不同，身体部位存在先后关系 |

原片的可信感来自动作因果和清晰的关键姿态，也使用夸张与省略。不能从这些帧反推出原片采用了 `9.81 m/s²`、某个质量或弹簧参数。本项目下面的单位和模型都是独立的实现约定。

## 如何把观察转成可复用方法

1. **蓄力要看得见。** 脚先支撑，髋部下降，躯干前倾，双臂后摆。更强的大跳保留更长的准备；蓄力结束后用更短的蹬伸形成速度对比。
2. **离地要带着速度。** 蹬地的末速度就是腾空的初速度。离地之后不再对整段时间套 ease-in-out；顶点减速来自重力，顶点也不是任意的停顿。
3. **着地要带着冲击。** 下落速度进入承重阶段，腿部压缩承接动量。允许很有弹性的回弹，但下一次弹起必须比第一次小，最后稳定下来。
4. **先约束支撑，再画关节。** 承重时脚尖固定，脚跟可以绕脚尖抬起；骨长固定，用膝部弯曲配合髋部高度。画面上的圆滑笔画不能掩盖断开的脚踝或拉长的腿。
5. **身体不是一根杆。** 上身角度滞后于驱动，头部和手臂有跟随与恢复；空中收腿、下落展腿以及双侧差异属于表演层。

## 为什么增加 TS 网页实现

[anything2explainer](https://github.com/Vincentwei1021/anything2explainer/tree/735c79c8724e897e8971cd59dde7e5aa11e4d6ce) 的模板使用 React / TypeScript / Remotion。研究了它的场景组合、公共缓动函数、渲染脚本与运动检查器，借鉴的是“时间函数驱动画面、公共模块可复用、导出后检查实际视频”的工程组织。

TS 并不会自动产生重力。它在这里的优势是浏览器里即时调参、任意拖帧、慢放和显示受力；同一个绘制函数又能用于导出。当前选择轻量的 **TypeScript + Canvas + Vite**：浏览器预览与 Playwright 逐帧导出共用 `draw()`，FFmpeg 编码视频和声音。无需为了三个动作预设引入整个应用框架；以后需要复杂镜头组合时，纯时间接口可以接入 Remotion。

该参考仓库采用 PolyForm Noncommercial 1.0.0。本项目没有复制其代码、字体或素材，物理、骨架、界面和导出脚本均独立实现；具体研究文件与许可边界见 [复用记录](upstream-reuse.md)。本项目继续使用自己的画面风格。

## 已实现与未覆盖

已实现自然跳跃、蓄力大跳、同样发力下更重的身体三种动作；使用有效身体质量、解析抛物线、被动弹簧阻尼落地与固定骨长骨架。说明与实际媒体见 [动作研究成片](../demos/weight/README.md)，复用方法见 [重量与弹性](../references/weighted-motion.md)。

这仍是可控的角色动画模型。它没有模拟所有肢体的独立质量、严格的全身质心、肌肉、完整摩擦锥、翻滚碰撞或任意地形；髋部只是动力学代理点。手臂和收腿属于编排动作，不应当被宣传成完整人体物理求解器。原有三支概念短片仍使用 Python 引擎，这次没有把它们的每个镜头迁移到 TS。
